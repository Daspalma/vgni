01 Objetivo e Escopo da Mudança

Implementação e entrega do EstuLanches para gestão de cardápio e pedidos da cantina escolar. Escopo contemplou conteinerização com Docker e Docker Compose, esquema e migrações no PostgreSQL com integridade referencial, cálculo de totais exclusivo no backend em centavos inteiros, transações atômicas para pedidos, interface responsiva em português e suíte automatizada de testes.

02 Componentes, Arquivos Alterados e Serviços

Serviço App (Porta 3000)Dockerfile baseado em node:24-alpine, NODE_ENV=production, usuário não-root node, npm ci --omit=dev, porta HTTP 3000 publicada no host e healthcheck ativo via /api/health.
Serviço DB (Porta 5432 interna)PostgreSQL 17 (postgres:17-alpine), isolado na rede interna do Compose (sem portas expostas no host), volume persistente postgres_data, healthcheck via pg_isready e credenciais via .env.
Arquivos do ProjetoDockerfile, docker-compose.yml, docker-compose.test.yml, .dockerignore, .env.example, package.json, src/ (app, domain, routes, services, db), db/, tests/ e docs/escalabilidade.md.
Integridade e SegurançaSQL 100% parametrizado, Helmet ativado (CSP, x-powered-by desabilitado), bloqueio de produtos com FOR SHARE, rollback total em falhas e persistência histórica de nomes e preços.

04 Validação de Containers e Pendências

Evidência do Docker: Arquivos de composição validados. O daemon do Docker Desktop no host Windows não pôde ser inicializado devido à falta de privilégios administrativos para acionar com.docker.service e à ausência de distros Linux no WSL 2. Nenhum log ou container foi forjado.
Pendência operacional: Instalar distribuição WSL 2 ou iniciar serviço Docker com perfil de administrador antes de executar docker compose up -d em produção.

05 Plano de Reversão e Segurança

Rollback de containers: Interromper com docker compose down (preserva o volume postgres_data). Em caso de reinstalação completa, aplicar backup do volume antes de qualquer ação destrutiva.
Segurança em produção: Não expor porta 5432 do banco; utilizar reverse proxy (Nginx/Traefik) com TLS/HTTPS válido; injetar credenciais via Secret Manager / vault; implementar rate-limiting e WAF.
